Frontend & UI/UX

  • Dead-link detection: if a link is invalid or expired, a "Vacancy unavailable" destructive toast appears and the card is greyed out (opacity + grayscale) — the vacancy cannot be re-clicked.
  • "Link verified" badge (emerald, BadgeCheck icon) shown beside each "Apply on employer site" button when the link has passed a liveness check. Unverified links show an amber "Link not yet verified" badge with a clock icon.
  • Sponsor vacancy cards show clickable vacancy count badges; careers-site fallback and honest empty states ("Contact details not yet available") displayed when no contact info is available.
  • Apply button labels updated to "Apply on employer site" (with a live link check spinner: "Checking link…") for clarity.
  • Cover Letter Generator accessible from any role card; AI-streams a personalised letter with Regenerate, Download .txt, and Copy actions.
🏢 Sponsor Licences Page
  • "Refresh Visible Page" button triggers a batch liveness check for all currently visible sponsor cards (up to 20 at a time).
  • 45-second per-user cooldown enforced server-side (HTTP 429); UI displays "Please wait — You refreshed recently" toast when triggered too soon.
  • On success: "Page refreshed" toast with breakdown: "N freshly checked · N up to date · N failed". If all cards were already fresh: "Already up to date — ⚡ All N visible employers were checked within the last 24 hours — job listings are completely up to date!"
  • Cached-24 h badge ("Checked Xm ago") briefly pulses (2.5 s highlight) after a refresh so candidates can see results re-rendered.
  • "All up-to-date" refresh message with animated timestamp pulse on the sponsor licences page confirming freshness.

  • Funnel and analytics breakdown (Total / Interviews / Offers / CV Sends) rendered as summary cards above the tab bar.
  • Mobile tracker also shows "Link Clicked" badge and icon, keeping both web and mobile in sync.

Backend & API Pipelines

🔗 Link Liveness & Outbound Tracking
  • GET /api/applications/track-outbound?vacancyId=&destinationUrl=: real-time liveness check on every outbound apply click. Returns INVALID_DEEP_LINK (HTTP 400) for aggregator/deep-link violations, JOB_EXPIRED (HTTP 410) for confirmed dead pages. Fail-open on timeouts so transient network errors don't block legitimate applications.
  • SSRF guard with per-redirect-hop private-host blocking — prevents server-side requests being weaponised to hit internal services during link checks.
  • Shared linkHealth checker + vacancyUrlPolicy blocklist: 6,647 aggregator URLs and 1,129 generic job-board landing pages purged — only direct employer URLs remain.
  • Sponsor links (source=sponsor): the aggregator blocklist and deep-link heuristics are explicitly bypassed, so NHS Jobs, Indeed, and other major job-board listings hosted by sponsor employers route correctly without triggering the aggregator gate.
  • Unified background liveness sweep with aggregator bulk-stamping — aggregator-domain URLs are bulk-stamped instead of checked individually, preventing infinite re-scan loops.
  • Admin full-scan endpoint available for manually triggered platform-wide sweeps.
🔄 Batch Check & Cooldown
  • Batch vacancy check endpoint: accepts up to 20 IDs per request; processes with a 15-worker concurrency pool.
  • 45-second per-user cooldown enforced server-side to prevent rate-limit abuse and protect external employer sites from excessive check traffic.
  • Cache-hit logic: vacancies verified within the last 24 hours are returned immediately from cache — no re-check triggered.
📬 Resend Email Ingestion
  • Resend inbound-email webhook: employer reply emails addressed to a JOBSAGE reply-to address are received, parsed, and mapped back to the originating application record.
  • Employer reply content automatically updates application status — e.g. a positive reply can trigger a transition to "Acknowledged" or further statuses.
  • Real employer email resolution for speculative CVs: AI enrichment discovers the correct employer contact email during vacancy checks and saves it for future sends, eliminating ops-fallback routing where possible.
🤖 AI URL Backfill & Contact Extraction
  • AI apply-URL backfill: vacancies missing an apply link are queued for AI discovery; results are logged to an admin review table before going live.
  • Contact extraction runs during vacancy checks — employer phone, email, and website are automatically saved to the role record and surfaced in the UI contact row.
  • PATCH /api/applications/:id/status validation now derived from the shared ApplicationStatus enum, preventing invalid status transitions at the API boundary.

Database & DevOps

📐 Schema Changes & Migrations
  • New columns on roles table: contactEmail, contactPhone, contactWebsite, applyUrl — enabling direct employer contact and tracked apply links from role listings.
  • New columns on sponsor_licence_vacancies and job_listings: livenessStatus, lastVerifiedAt, livenessReason — along with database indexes for efficient querying.
  • Migration 0006: idempotent DDL sync repairing pre-existing schema drift between the ORM model and the live database — applied without downtime.
  • Migration 0007: constraint rename pass ensuring all foreign-key and unique constraints match Drizzle-generated names, eliminating push-drift warnings.
  • Startup schema-drift check: the API server now logs loud warnings on boot if the live DB schema diverges from the ORM model, providing an early warning system before any deploy.
🚀 Production Migration
  • Production preferred_region scalar text → text[] (array) migration executed with a USING ARRAY[col]::text[] cast — preserving existing single-region values as single-element arrays while enabling multi-region selection going forward.
  • Platform republished post-migration with zero reported downtime.
  • Vitest regression suite for the liveness-sweep logic added — prevents future regressions in bulk-stamping and dead-link detection.
  • OpenAPI contract updated to reflect all new endpoints and request/response shapes.

Chrome Extension — Smart Apply

🔌 Manifest V3 Scaffold
  • Full Chrome Extension Manifest V3 scaffold built from scratch: service worker background script, content script, and sidebar injection.
  • CORS issue resolved — extension background script can now make authenticated requests to the JOBSAGE API without cross-origin errors.
  • Pill toggle injected into employer job pages via content script — candidates can activate the JOBSAGE sidebar overlay directly on the employer's site.
  • Complete dist/ build pipeline configured; bundle-integrity QA tests verify the extension package is well-formed before release.
🤖 Smart Apply SSE Integration
  • Smart Apply assistant accepts extension-scraped job context over a Server-Sent Events (SSE) stream, authenticated with a Bearer token.
  • Context payload includes: question, jobTitle, employer, and jobDescription — allowing the AI to generate role-specific answers without the candidate re-entering job details.
  • Real-time streaming responses delivered token-by-token to the sidebar UI, providing immediate feedback even for long AI responses.

Step-by-Step QA Testing Guide

Audience: QA testers and non-technical stakeholders. All test cases target the live JOBSAGE web application. Sign in as a candidate account before running tests TC-01 through TC-06. Estimated total time: ~30 minutes.

Environment: JOBSAGE web app (/ — the candidate-facing interface). An active candidate account with at least one Preferred UK Region set in Profile is recommended.

1
Active jobs show "Link verified" badge; dead links are hidden & greyed
CRITICAL
Route /opportunities Feature Link liveness badges & dead-link suppression
  1. 1 Sign in as a candidate and navigate to Opportunities in the sidebar.
  2. 2 Scroll through the job board (the "Board" tab is active by default). Look for role cards that display an "Apply on employer site" button.
  3. 3 Locate a card showing the emerald "Link verified" badge (✓ BadgeCheck icon, green pill) beside the apply button. This confirms the link passed a recent health check.
  4. 4 Locate a card showing the amber "Link not yet verified" badge (clock icon, amber pill). These links will be checked shortly by the background sweep.
  5. 5 Attempt to find or simulate a dead link: click any "Apply on employer site" button and observe the response.
    — If the URL is dead/expired: a red destructive toast appears: "Vacancy unavailable — This vacancy is no longer accepting applications (closed by employer)."
    — The card should become greyed-out (opacity + grayscale) and the button replaced with "Vacancy closed" (non-clickable).
  6. 6 Confirm that no dead-link cards appear in the primary list without the visual greyed state — they should not be shown as active to candidates.
✅ Expected: Verified badges are emerald green. Dead links trigger a toast and grey the card immediately. No dead vacancy appears as fully active in the job list.
2
"Refresh Visible Page" on Sponsor Vacancies + 45-second cooldown
HIGH
Route /sponsor-licences Feature Batch liveness refresh & per-user rate limiting
  1. 1 Navigate to Sponsor Licences in the sidebar.
  2. 2 Wait for the employer cards to load. Locate the "Refresh Visible Page (N)" button near the top of the list area — where N is the count of currently visible employer cards.
  3. 3 Click the button. It should immediately enter a loading state labeled "Refreshing this page…"
  4. 4 After a few seconds, a success toast appears: "Page refreshed — N freshly checked · N up to date". The "Checked Xm ago" timestamps on sponsor cards briefly pulse/highlight.
  5. 5 If all cards were already checked within the last 24 hours, the toast instead reads: "Already up to date — ⚡ All N visible employers were checked within the last 24 hours — job listings are completely up to date!"
  6. 6 Cooldown test: Immediately click "Refresh Visible Page" again within 45 seconds. A warning toast should appear: "Please wait — You refreshed recently — please wait a moment before trying again." The button should not re-trigger a check.
  7. 7 Wait at least 45 seconds and click the button once more. It should succeed without a cooldown warning.
✅ Expected: First click refreshes visible cards and shows results toast. Second click within 45 s shows "Please wait" toast only. Timestamp badges animate after a successful refresh.
⚠️ The button label includes the count in parentheses, e.g. "Refresh Visible Page (20)" — the max batch size is 20 employers per request regardless of how many are visible.
3
External "Apply" click creates a Tracker entry with "Link Clicked" status
CRITICAL
Routes /opportunities → /applications Feature Outbound apply tracking + tracker "Link Clicked" status
  1. 1 Navigate to Opportunities and find a role card that has an "Apply on employer site" button (indicating a direct employer apply URL).
  2. 2 Click "Apply on employer site". The button briefly shows "Checking link…" while the server validates the URL.
  3. 3 If the link is valid: a new browser tab opens to the employer's site, and a success toast appears: "Application logged! — Track your progress under the 'Company Website' tab in your Tracker."
  4. 4 Navigate to Applications (Application Tracker) in the sidebar.
  5. 5 Click the "Company Website" tab (the second tab, after "All").
  6. 6 Confirm that a new entry is visible for the employer/role just applied to, with the status badge showing "Link Clicked" (slate/grey badge with an ExternalLink icon) and the type badge showing "Company Website" (blue outline, Globe icon).
  7. 7 Click the "Link Clicked" status badge on the card to open the status dropdown. Confirm the available statuses include: Link Clicked, Applied, Shortlisted, Under Review, Interview, Interview Invited, Offer, Rejected, No Response.
✅ Expected: Toast confirms the click. Application appears in Tracker → "Company Website" tab with "Link Clicked" status. Status is updatable via the inline dropdown.
4
Sponsor apply links to job boards (Indeed / NHS) are not blocked by aggregator gates
HIGH
Route /sponsor-licences (vacancy cards) Feature source=sponsor bypass of aggregator blocklist
  1. 1 Navigate to Sponsor Licences and browse to a sponsor company card that lists open vacancies (a badge showing a vacancy count — e.g. "3 vacancies").
  2. 2 Expand or click the sponsor card to view its vacancy list. Look for a vacancy whose apply link points to a job board (e.g. NHS Jobs at jobs.nhs.uk, or Indeed at indeed.co.uk).
  3. 3 Click the apply / link button for that vacancy.
  4. 4 Verify that the action succeeds — the external tab opens and a success toast is shown. No error toast saying "This destination is a third-party job aggregator and cannot be tracked" should appear.
  5. 5 As a contrast check: attempt the same click from a non-sponsor vacancy whose apply URL is a generic aggregator search-results page (e.g. a search URL, not a direct job listing). This should fail with the aggregator error toast.
✅ Expected: Sponsor vacancy links to NHS Jobs / Indeed open successfully without triggering the aggregator block. Generic aggregator search-page URLs from non-sponsor roles are still blocked with an appropriate error.
ℹ️ The source=sponsor query parameter on the tracking endpoint is what bypasses the aggregator gate. This is automatic when the apply button is on a sponsor vacancy card.
5
"Company Website" tab is second in the Tracker; status update works there
MEDIUM
Route /applications Feature Tracker tab order & inline status dropdown
  1. 1 Navigate to Applications in the sidebar. The page title is "Application Tracker".
  2. 2 Observe the four tabs in the tab bar. Confirm the left-to-right order is exactly: All · Company Website · Via JOBSAGE · Speculative CV.
  3. 3 "Company Website" must be in position 2 (second from left, after "All"). If it appears in another position, this is a regression.
  4. 4 Click "Company Website". Confirm that applications of kind website are shown — cards will carry a blue "Company Website" type badge (Globe icon).
  5. 5 On any application card in the "Company Website" tab, click the status badge (e.g. "Link Clicked") to open the status dropdown.
  6. 6 Select "Applied" from the dropdown. The badge should animate to show a spinner, then update to "Applied" (blue badge, ClipboardList icon).
  7. 7 Refresh the page and confirm the status change persisted.
✅ Expected: Tab order is All → Company Website → Via JOBSAGE → Speculative CV. Status update saves correctly and persists after page refresh.
6
Multiple preferred regions selectable in Profile; job matching respects them
HIGH
Routes /profile → /opportunities Feature Multi-select preferred region + job match filtering
  1. 1 Navigate to Profile in the sidebar.
  2. 2 Scroll to the "Preferred UK Region(s)" label. It renders a grid of checkboxes (2–3 columns) listing all UK regions.
  3. 3 If all checkboxes are currently unchecked, a "not set" indicator (red/amber badge) is shown below the grid — confirm this is visible.
  4. 4 Check two or more regions (e.g. "London" and "South East England"). Each tick auto-saves — no separate Save button click is required.
  5. 5 Confirm both selected regions are visually checked after the auto-save completes (the checkboxes should remain ticked after ~300 ms).
  6. 6 Navigate to Opportunities. The AI match strip ("Your Best Matches Right Now") and the job board results should now include roles from both selected regions.
  7. 7 Return to Profile and uncheck one region. Navigate back to Opportunities and confirm the results adjust (roles from the unchecked region are no longer prioritised in matches).
  8. 8 Optional: Check all boxes then uncheck all — the "not set / open to any UK location" helper text should appear below the grid.
✅ Expected: Multiple regions can be simultaneously checked. Auto-save works without a separate Save action. Opportunities page reflects the updated preferences in match scoring.
ℹ️ The helper text reads: "Select one or more UK regions where you'd prefer to work. Leave all unchecked if you're open to any UK location."
