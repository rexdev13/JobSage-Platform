3. Persistence and entitlement rules

  • users: plan defaults to free and permits only free/pro; bonus_readiness_checks defaults to zero and cannot be negative; subscription_expires_at is nullable; stripe_customer_id and stripe_payment_intent_id exist but no operational reads/writes were found beyond their definitions.
  • role_gap_analyses and sponsor_licence_gap_analyses: per-user analysis/cache records provide monthly usage counts through generated_at. These are not payment or subscription ledgers.
  • support_tickets: Account/Billing is a ticket category, not a billing transaction type.
  • No dedicated subscription, payment, invoice, checkout-session, provider-event or trial table was found in the database source.
  1. An unexpired Pro entitlement permits unlimited new Readiness analyses.
  2. Otherwise, allow new analyses while the current UTC month count is below ten.
  3. Once that allowance is used, atomically decrement one bonus check if available.
  4. Otherwise deny with HTTP 429. Both role and sponsor-vacancy analysis paths use the shared helper.
  5. Existing analyses use a seven-day cache. Stale refreshes bypass initial quota reservation. Failed analyses refund a reserved bonus check.
  6. The monthly boundary is 00:00 UTC on the first of each month. Expired Pro is treated as free without clearing the stored plan field.

5. Important inconsistencies and gaps

  1. Two unrelated public price catalogs. Annual Individual/Premium/Institutional GBP plans do not correspond to free/pro or the USD booster/Pro products. There is no single price/entitlement source.
  2. Paid-upgrade recovery can remain blocked in an already mounted analysis sheet. A 429 sets local limitReached=true and disables its analysis query. It clears only when the legacy usage endpoint reports used < limit. Buying bonus checks or activating Pro does not reduce used, and checkout invalidates only the newer quota query. This is a static code finding, not a browser-reproduced paid journey.
  3. Quota UI sources disagree. The newer quota endpoint caps used at ten and includes plan/bonus state; the legacy usage endpoint returns the raw monthly total and omits both. The analysis-sheet badge can therefore show exhausted/red usage for an allowed Pro/bonus user. The sidebar likewise shows the numerical monthly counter instead of “Unlimited”.
  4. Ten is duplicated. It appears in the server constant, OpenAPI const, generated TypeScript literal types, modal fallback, analysis-sheet/support/admin text and tests. The requested three-check policy is not current code.
  5. “Free refresh” is not a separate consumption ledger. Usage is derived from current-month generated_at timestamps. Refreshing an old analysis rewrites generated_at, so it can affect later monthly counts despite bypassing reservation at refresh time.
  6. Free allowance is not atomically reserved. The monthly path checks a count then allows work, unlike the conditional atomic bonus decrement. Concurrent new requests may exceed the intended free cap; this risk was not load-tested.
  7. Subscription duration is access time, not verified recurring billing. Sandbox Pro adds one calendar month from the later of now/current expiry. No provider subscription ID, renewal webhook, trial transition or price validation is present.
  8. Paid-journey test gaps. No dedicated checkout-route or quota-modal paid-upgrade test file was found. Existing tests do not establish real payment or post-upgrade sheet recovery.
  9. Admin reset is destructive to analysis history. It deletes both types of stored analysis, rather than resetting an independent usage counter; it leaves subscription/bonus fields unchanged.

6. Verification and limits

Focused existing tests passed: API quota, sponsor analysis and role analysis — 3 files / 11 tests; analysis-sheet frontend — 1 file / 3 tests. These are unit/component tests with mocks, not live payment tests. The guest landing page loaded in the application preview without visible runtime errors. No checkout, webhook, purchase, admin reset or support-ticket mutation was exercised.
