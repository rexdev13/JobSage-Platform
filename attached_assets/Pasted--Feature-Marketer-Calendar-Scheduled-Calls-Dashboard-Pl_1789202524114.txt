### Feature: Marketer Calendar & Scheduled Calls Dashboard

Please implement a fully functional **Marketer Calendar & Scheduling System** on the Marketer dashboard (`artifacts/jobsage-web/src/pages/admin/AdminLeadsPage.tsx`) directly below the Waitlist Leads table, along with supporting backend routes and schema.

---

#### 1. Database Schema (`lib/db/src/schema/marketerEvents.ts`)
Create a table for scheduled marketer calls and meetings:
- `id`: serial primary key
- `marketingUserId`: varchar referencing `usersTable.id` (onDelete: cascade, notNull)
- `leadId`: integer referencing `socialLeadsTable.id` (onDelete: set null, nullable)
- `title`: text, not null (e.g. "Discovery Call with Jane Doe")
- `scheduledAt`: timestamp with timezone, not null
- `endTime`: timestamp with timezone (default: scheduledAt + 30 mins)
- `meetingUrl`: text (defaults to marketer's Calendly URL or custom Google Meet / Zoom link)
- `status`: varchar enum: `['scheduled', 'completed', 'cancelled', 'rescheduled', 'no_show']` (default: `'scheduled'`)
- `notes`: text (pre-call agenda or post-call notes)
- `source`: varchar enum: `['manual', 'calendly']` (default: `'manual'`)
- `createdAt`: timestamp with timezone, default now

Export the table and register it in `lib/db/src/schema/index.ts`. Run migrations / push schema as appropriate.

---

#### 2. Backend Routes (`artifacts/api-server/src/routes/marketerCalendar.ts`)
Create endpoints protected by `requireAuthenticated`:
1. `GET /api/marketer/calendar/events`:
   - Query params: `start` (ISO date), `end` (ISO date), `marketingUserId` (optional).
   - Scoping:
     - Marketers (`role === 'marketing'`) can **only** fetch their own events (`marketingUserId === req.user.id`).
     - Admins / Super Admins (`role in ['admin', 'super_admin']`) can view events for any specific marketer or all marketers if `marketingUserId` is omitted.
   - Join with `socialLeadsTable` to return lead details (`firstName`, `lastName`, `email`, `phone`, `industrySector`, `status`).
2. `POST /api/marketer/calendar/events`:
   - Body: `{ leadId?, title, scheduledAt, endTime?, meetingUrl?, notes? }`.
   - Creates the event for `req.user.id` (or specified marketer if Admin).
   - If `leadId` is provided, automatically set `socialLeads.status = 'contacted'` and update `contactedAt = now()` if the lead was previously `'new'`.
3. `PATCH /api/marketer/calendar/events/:id`:
   - Body: `{ scheduledAt?, endTime?, status?, notes?, meetingUrl? }`.
   - Marketers can update their own events; Admins can update any.
4. `DELETE /api/marketer/calendar/events/:id`:
   - Cancels or deletes the event.
5. (Bonus) `POST /api/webhooks/calendly`:
   - Webhook endpoint that receives Calendly `invitee.created` payloads:
     - Matches `invitee.email` against `social_leads.email`.
     - Automatically creates a `scheduled` event and links it to the lead.

Register these routes in `artifacts/api-server/src/app.ts`.
