8. Recommended integration plan
Design the final automated flow using the existing JOBSAGE scheduler/cron system.

The target design should be:

A. Feed discovery job
- Runs automatically on sponsor employers with saved website/careers URL.
- Finds verified direct ATS/feed mappings only.
- Stores provider, board ID/token, evidence URL, confidence/status, last checked time.
- Does not create candidate-visible vacancies directly.
- Does not accept guessed board IDs unless employer-site evidence confirms it.

B. Direct-feed vacancy import job
- Runs automatically on verified mappings.
- Pulls actual vacancies from Greenhouse/Ashby/Lever/etc.
- Stores exact detail URL and application URL separately where available.
- Uses stable external listing IDs/hashes for dedupe.
- Updates existing vacancies on repeat runs.
- Marks missing/closed vacancies safely only after confirmed full feed success.
- Does not run generic HTML crawl.

C. Liveness verification job
- Rechecks detail/apply URLs.
- Marks broken/closed/stale vacancies correctly.
- Does not treat “page is reachable” as proof that it is a real vacancy.

D. Candidate visibility rules
- Candidate-visible company-site vacancies should require strong evidence:
  - known ATS/direct feed posting, or
  - schema.org JobPosting with specific role and application/contact route, if explicitly enabled later.
- Generic HTML link discoveries should not become candidate-visible vacancies for now.
