KNOWN LOCAL CODE FINDINGS TO VERIFY
======================================================================

Inspect the current Replit code rather than assuming local line numbers are unchanged.

The previously inspected code showed:

1. regionMatching.ts

regionsFromLocationText("New York, NY") correctly returns [].

However, regionsOverlap() treats an empty target-region list as eligible everywhere. Therefore foreign locations become “unknown” and survive preference filtering.

2. sponsorVacancyRoles.ts

fetchSponsorVacanciesAsRoles() checks liveness, profession and URL evidence but does not require confirmed UK location before returning candidate-visible roles.

It defaults a missing location to “United Kingdom,” which is unsafe. Missing location evidence must not be converted into UK evidence.

3. companySiteScheduler.ts

The scheduler calculates ukLocationKnown after selecting/persisting eligible adverts. It records a metric but does not consistently use confirmed UK location as a persistence gate.

4. boardVacancyPipeline.ts

upsertSharedBoardVacancies() has no central UK-location eligibility check. Foreign or unknown-location rows can therefore be inserted or updated.

5. roles.ts

Candidate-facing role lists rely on preferred-region overlap. Empty targetRegions remain visible.

The main roles, my-matches, recommended roles and Send CV data all require review.

6. sponsorLicences.ts

The sponsor vacancy panel filters liveness but does not consistently filter confirmed UK location.

Its vacancy counts and top-match queries can count foreign vacancies.

7. opportunityFilters.ts and sponsorVacancyFilters.ts

The browser treats empty targetRegions as visible. Browser filtering must not be the primary security boundary, but it should also reject records explicitly marked non-UK.

8. alertScheduler.ts

Alerts use the same permissive region-overlap behaviour and may send foreign vacancies.

9. Send CV

roles.ts and sponsorLicences.ts previously contained unconditional:

sendCvEligible: true

This can label vacancies “Employer email available” or expose Send CV even when no verified recruitment route exists. Audit and correct this while fixing foreign vacancy visibility.

10. atsDirectoryBootstrap.ts

isClearlyUkAtsAdvert() already rejects New York and bare Remote. Reuse a shared policy rather than keeping this safety rule in only one ingestion path.

1. CREATE ONE SHARED LOCATION POLICY
======================================================================

Create a single reusable server-side location classifier, for example:

classifyUkVacancyLocation(...)

It must return:

- confirmed_uk
- confirmed_non_uk
- unknown

Use all available structured evidence:

- location text
- targetRegions
- source-provided country/country code
- structured ATS location fields
- UK postcode
- explicit UK nation or region
- source metadata where authoritative

Rules:

A vacancy is confirmed_uk when it has reliable evidence such as:

- United Kingdom, UK or GB
- England
- Scotland
- Wales
- Northern Ireland
- Valid UK postcode
- Recognised UK region/county/city
- “Remote UK” or equivalent explicit UK remote wording
- A structured country code of GB/GBR

A vacancy is confirmed_non_uk when it has explicit foreign evidence, including:

- United States, USA or US
- Canada
- Foreign country names/codes
- US state names or state abbreviations in location context
- Canadian province names or abbreviations
- Explicit foreign cities/regions
- Structured country code other than GB/GBR

Foreign evidence must take precedence over ambiguous city names.

Required examples:

- London, UK → confirmed_uk
- London, England → confirmed_uk
- Remote - UK → confirmed_uk
- Manchester → confirmed_uk when matched deterministically
- Edinburgh, Scotland → confirmed_uk
- Belfast, Northern Ireland → confirmed_uk
- San Francisco, CA → confirmed_non_uk
- New York, NY → confirmed_non_uk
- Austin, TX → confirmed_non_uk
- Toronto, ON → confirmed_non_uk
- Montréal, Quebec, Canada → confirmed_non_uk
- London, Ontario → confirmed_non_uk
- Cambridge, MA → confirmed_non_uk
- Manchester, NH → confirmed_non_uk
- Birmingham, Alabama → confirmed_non_uk
- York, PA → confirmed_non_uk
- Remote → unknown
- Worldwide → unknown
- Multiple locations → unknown
- Empty/null → unknown
- United Kingdom and New York → confirmed_uk only if the advert explicitly states the role is available in the UK

For JobSage candidate visibility:

ONLY confirmed_uk is allowed.

confirmed_non_uk and unknown must remain hidden until better evidence is obtained.

Do not globally change region-preference semantics in a way that breaks unrelated uses. Apply UK eligibility first, then apply candidate region preferences.
