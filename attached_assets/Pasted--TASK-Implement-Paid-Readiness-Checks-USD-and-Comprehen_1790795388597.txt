### 2. Pricing Tiers (USD)
1. **Check Booster Pack**: **$5.99** for **25 additional checks** (one-time purchase).

- Add subscription/credit tracking to `usersTable` (or a dedicated `user_subscriptions` table in `lib/db/src/schema/auth.ts` or `subscriptions.ts`):
  - `plan`: varchar enum (`"free"`, `"pro"`) default `"free"`
  - `bonusReadinessChecks`: integer default 0
  - `subscriptionExpiresAt`: timestamp with time zone (nullable)
  - `stripeCustomerId`: text (nullable)
  - `stripePaymentIntentId`: text (nullable)
- Generate and run the Drizzle migration.

### 4. Quota Service Refactor (`artifacts/api-server/src/lib/readinessQuota.ts`)
- Refactor quota check function to accept candidate user profile:
  - If `user.plan === "pro"` (and `subscriptionExpiresAt` is in the future): bypass monthly cap (unlimited).
  - Else if `user.bonusReadinessChecks > 0`: decrement one bonus credit and allow check.
  - Else: enforce default `READINESS_CHECK_LIMIT = 10` per calendar month.
- Expose an endpoint `GET /api/readiness/quota` returning:
  `{ used: number, limit: number, bonusRemaining: number, plan: "free" | "pro", resetsAt: string }`

### 5. Checkout & Webhook Routes (`artifacts/api-server/src/routes/checkout.ts`)
- `POST /api/checkout/create-session`:
  - Accepts `{ type: "booster_pack" | "pro_subscription" }`
  - Creates a Stripe Checkout session ($5.99 one-time or $19.99/mo subscription) with `success_url` and `cancel_url`.
  - In development without live Stripe keys, provide a clean mock/sandbox completion flow.
- `POST /api/checkout/webhook`:
  - Listens for `checkout.session.completed` / `invoice.payment_succeeded`.
  - Automatically updates the user's bonus checks (+25) or sets plan to `"pro"`.

### 6. Quota Upgrade Modal (`artifacts/jobsage-web/src/components/ReadinessQuotaModal.tsx`)
- Appears when a user reaches the 10-check limit or clicks their readiness quota pill.
- Shows usage bar (`10/10 monthly checks used`).
