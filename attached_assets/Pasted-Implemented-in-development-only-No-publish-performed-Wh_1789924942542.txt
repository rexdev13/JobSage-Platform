Implemented in development only. No publish performed.

## Why Reed coverage was tiny

Production currently has:

| Board | Live | Dead | Total |
|---|---:|---:|---:|
| NHS Jobs | 2,494 | 265 | 2,767 |
| Reed | 7 | 1 | 8 |

The main Reed failure was parser drift:

- Reed still returns `data-qa="job-card"` and `data-qa="job-card-title"`.
- The parser required `data-qa="company-name-link"`.
- Current Reed cards now put the employer in the recruiter link inside `data-qa="job-posted-by"`.
- As a result, current cards were discarded before the existing strict employer-name match could run.

This explains why Reed has only a handful of stored rows. Liveness is not the primary blocker: 7 of the 8 production Reed rows are already live.

The approximately five visible Reed vacancies are also explained by classification:

- 2 live NMC
- 2 live HCPC
- 1 live GMC
- 2 live but unclassified, so excluded from candidate-facing category results

Production logs also show Reed rate-limit/backoff events. Those remain protected by the existing cooldown logic and were not weakened.

## Minimal fix

Added a fallback employer extractor that:

1. Uses the existing `company-name-link` marker when available.
2. Falls back to the recruiter link inside `job-posted-by` for current Reed markup.
3. Keeps the existing strict employer-name matching.
4. Keeps deep-link validation and all evidence/liveness behavior unchanged.

No crawl limits were changed.
