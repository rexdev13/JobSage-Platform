9. ACCOUNT DELETION
==================================================

Implement complete account-deletion support.

APPLE REQUIREMENT

Users who can create accounts must be able to initiate deletion inside the app.

GOOGLE REQUIREMENT

Users who can create accounts must have:

1. An in-app path to request account and associated-data deletion.
2. A public web page through which they can request deletion outside the app.

IN-APP FLOW

Place:

Profile or Settings
→ Privacy, Legal & Account
→ Delete Account

The flow must:

1. Explain that deletion affects the complete JOBSAGE account.
2. Explain which information will be deleted.
3. Explain any information legally retained and why.
4. Explain backup-removal timing.
5. Explain the effect on active applications and employer communications.
6. Explain subscription cancellation separately if applicable.
7. Require recent authentication or reauthentication.
8. Use a clear destructive confirmation.
9. Avoid dark patterns.
10. Allow the user to cancel before final confirmation.
11. Confirm successful request submission.
12. State whether deletion is immediate or scheduled.
13. Send a confirmation email without exposing sensitive data.
14. Sign the user out and revoke active sessions at the correct point.
15. Provide final completion confirmation if deletion is asynchronous.

Do not offer only:

- Account deactivation
- Logout
- Emailing support
- A generic contact form
- Removing the app
- Deleting profile fields while retaining the account

Those are not complete account deletion.

PUBLIC WEB FLOW

Implement:

/account-deletion

This page must be directly accessible without first entering the main app.

It must:

- Explain how deletion works
- Identify the app and developer
- Allow the user to authenticate and submit a deletion request
- Provide account-verification safeguards
- Explain data deleted
- Explain retained data
- Explain expected completion time
- Provide support contact information
- Avoid exposing whether an email address has an account
- Rate-limit request attempts
- Protect against CSRF and account-takeover abuse

11. PERMISSIONS AND PROMINENT DISCLOSURES
==================================================

Audit every native permission and remove unused permissions.

Possible permissions include:

- Camera
- Photo library
- Document selection
- Notifications
- Location
- Calendar
- Microphone
- Storage

For each permission document:

- Feature requiring it
- Whether it is necessary
- Platform
- Store declaration
- In-app explanation
- Timing
- Denial behaviour

Permission rules:

- Request permission only when the user activates the relevant feature.
- Explain the purpose before the operating-system dialog where appropriate.
- Do not request every permission at first launch.
- The app must remain usable when an optional permission is denied.
- Provide a Settings link when a denied permission is required later.
- Permission wording must match actual behaviour.
- Do not request location unless a concrete user-facing feature requires it.
- Do not use Accessibility Service for Smart Apply.
- Do not request broad storage access when system document pickers are sufficient.
- Do not request tracking permission unless the app actually performs cross-app tracking.

If a sensitive permission requires Google prominent disclosure, show the disclosure immediately before the permission request.

A privacy-policy link does not replace a required prominent disclosure.

25. DEFINITION OF DONE
==================================================

The work is complete only when:

- Privacy Policy is publicly accessible and linked inside the app.
- Terms are publicly accessible and linked inside the app.
- EULA strategy is documented and implemented appropriately.
- Login screens contain the relevant legal/support links.
- Registration contains clear Terms and Privacy acceptance.
- Optional marketing consent is separate.
- Settings contains Privacy, Legal & Account.
- In-app account deletion can be initiated.
- Public web account deletion exists.
- Deletion covers associated data or transparently documents lawful retention.
- Data-export/privacy-choice handling exists.
- Native permissions are minimal and requested contextually.
- Apple privacy-label answers are drafted from actual data flows.
- Google Data Safety answers are drafted from actual data flows.
