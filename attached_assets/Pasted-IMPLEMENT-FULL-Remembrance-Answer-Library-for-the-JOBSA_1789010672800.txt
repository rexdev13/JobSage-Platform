IMPLEMENT FULL Remembrance / Answer Library for the JOBSAGE Chrome extension.
This is a client-requested full feature: when a candidate enters a value the extension didn’t have, save it and reuse it on future applications for similar questions. Not page-only memory.

Extend existing answerMemory.ts + related UI/detector/prefill code. Do not force-push.

==================================================
PRODUCT GOAL
==================================================
When a candidate fills a form field that JOBSAGE had no value for:
1) Automatically remember that answer (with clear UX)
2) On later job applications (different pages/employers/ATS forms), detect similar questions
3) Prefill from remembered answers
4) Let the candidate review, edit, and delete remembered answers

This must feel like a real answer library, not “same page cache.”

==================================================
NON-NEGOTIABLE SAFETY (still required for full feature)
==================================================
- Save ONLY candidate-authored input (not profile autofill, not AI insert, not memory restore echoing itself)
- NEVER remember: passwords, OTP, NI/SSN/passport, bank/tax, health/disability, criminal/DBS, equality/diversity, RTW/sponsorship, consent/declarations, files
- Unknown/ambiguous sensitivity => do not auto-remember
- Never overwrite a non-empty field
- Candidate typing always wins
- Show when a value came from memory: “Saved from a previous application”
- Provide clear manage/delete controls

==================================================
DATA MODEL
==================================================
Replace/upgrade raw string storage to versioned Answer Library records, e.g.:

RememberedAnswer {
  id
  version
  value
  normalizedQuestion
  questionSignature
  labelVariants[]
  controlType
  category: "safe_free_text" | "safe_structured" | ...
  source: "candidate"
  scope: "global" | "employer" | "ats"
  originHost?
  employerKey?
  atsKey?
  createdAt
  updatedAt
  lastUsedAt
  useCount
  expiresAt? (optional long TTL or none for library items explicitly saved)
  explicitSave: boolean
}

Storage:
- Local extension storage first (chrome.storage.local), new prefix jobsage_answer_library_v1
- Keep page-memory and library distinct if needed
- Bound max entries / value length
- Migration from old answerMemory keys where possible

Optional backend sync (if feasible in-repo without huge scope):
- If auth + API patterns exist, add remembered-answer endpoints and sync
- Otherwise ship full local cross-application library now, with sync stub/TODO clearly marked
- Do NOT dump into smart_apply_drafts or application notes

==================================================
CAPTURE / SAVE BEHAVIOR
==================================================
- Detect candidate input via input/change/blur
- Suppress extension-driven writes with provenance markers
- Auto-save eligible safe answers when:
  - field had no prior JOBSAGE value, AND
  - candidate entered a meaningful value, AND
  - field passes eligibility policy
- For long narrative answers, auto-save is OK if safe; show subtle “Saved for future applications”
- For borderline structured fields (e.g. professional registration if classified safe), allow save
- Selects/radios: include if safely classified and value is stable text option label/value
- Checkboxes/files: do not store files; consent checkboxes excluded

==================================================
RECALL / MATCHING (FULL FEATURE)
==================================================
Prefill precedence:
1. existing non-empty DOM value
2. current candidate typing
3. Answer Library high-confidence match
4. exact profile value
5. structured-prefill API
6. AI generate
7. empty

Matching strategy (implement now):
1) Exact normalized question + control type
2) Exact signature match across pages
3) High-confidence fuzzy/similar question text match
   - normalize punctuation/case/whitespace
   - compare label similarity (token overlap / Levenshtein / equivalent)
   - require confidence threshold (e.g. >= 0.86) before autofill
4) Optional synonym map for common application questions:
   - “why do you want this role”
   - “motivation for applying”
   - “supporting statement”
   - etc.

Rules:
- If multiple candidates match, pick best confidence; if close collision, do not autofill — show chooser or skip
- Prefer same employer/ATS match as slight boost, but allow cross-employer for generic questions
- Employer-specific answers (detected by org names in value or highly specific wording) should prefer same-employer scope or require higher confidence
- Recalculate on each scan/step change
