C) Closed / expired date enforcement (CRITICAL)
----------------------------------------

Problem to fix:
Candidates still see jobs that are already closed. The advert text / structured fields include a closing date that has passed, but the apply URL still returns HTTP 200 / “page exists”. This is especially common on NHS Jobs / NHS-related sources, and also appears on Reed and other boards. HTTP 200 must NEVER keep an expired job candidate-visible.

Requirements:

1) Persist closing/expiry when extracted:
   - closesAt / expiresAt / closingDate / applicationCloseDate (use existing field names if present; add additive columns only if needed)
   - Parse UK date formats from listing + detail pages and structured data (JSON-LD validThrough, NHS closing date fields, “Closing date:”, “Apply by”, “Closes on”, etc.)
   - Store timezone-safe UTC; treat date-only values as end of that UK calendar day unless source gives a time.

2) Hard rule for candidate visibility:
   If closesAt/expiresAt is present AND now > closesAt/expiresAt → status = "expired" / hide from candidates.
   Do this even if:
   - liveness = live
   - URL returns 200
   - page still loads
   - last_verified_at is recent

3) During liveness / board refresh / company-site upsert:
   - Re-parse closing date from page when present.
   - If page text clearly says closed/filled/no longer accepting applications → mark dead/closed and hide.
   - If closing date has passed → mark expired and hide (prefer expired over dead when only the date passed).
   - If no closing date found → fall back to existing freshness/missing rules (do NOT invent a fake expiry).

4) Apply this to ALL candidate-facing paths, especially:
   - NHS Jobs / job_board vacancies
   - company-site vacancies
   - Opportunities list + counts
   - matches / alerts
   - vacancy detail pages

5) Backfill / cleanup on deploy:
   - One-time pass (or first successful board/liveness runs) to hide already-stored vacancies whose stored closing date is in the past.
   - Log how many were hidden as expired.

6) Tests (must add):
   - NHS vacancy with past closing date + live URL → NOT candidate-visible
   - NHS vacancy with future closing date + live URL → visible (if other rules pass)
   - Board vacancy with validThrough / closesAt in the past → expired/hidden
   - Vacancy with no closing date + live + recent verification → still uses freshness rules only
   - Page says “This vacancy has closed” / “no longer accepting applications” → hidden
   - Company-site vacancy whose listing still 200 but closing date passed → hidden

Returning:
"visible" | "stale" | "missing" | "dead" | "expired" | "unverified"

Visibility rules (all must pass for "visible"):
1. Has specific vacancy evidence (company-site) OR is a valid board vacancy
2. Observed in latest COMPLETED source crawl (company-site) / recently refreshed (board)
3. liveness = live
4. last_verified_at is recent enough for that source type
5. source_missing_since IS NULL
6. closesAt/expiresAt is NULL OR now <= closesAt/expiresAt
7. page does not explicitly say closed/filled

Priority of negative states:
- explicit closed/dead on page → dead
- closing date passed → expired
- missing from completed crawl → missing
- not recently verified → stale / unverified

Partial / failed / robots / timeout crawls MUST NOT mark existing vacancies missing.
