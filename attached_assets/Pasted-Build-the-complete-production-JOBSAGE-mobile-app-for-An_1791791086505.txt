2. PRODUCT GOAL
==================================================

Turn artifacts/jobsage-mobile into the full JOBSAGE application for iOS and Android.

The completed app must:

1. Present the complete responsive JOBSAGE website experience.
2. Include every candidate, employer, reviewer, admin, marketing and super-admin feature available to that role.
3. Preserve the JOBSAGE visual identity, navigation wording, data, actions and business logic.
4. Feel intentional, polished and intuitive on a phone.
5. Recreate the useful Chrome extension functionality inside a controlled in-app Smart Apply browser.
6. Be buildable and submittable from Windows using Expo EAS.
7. Continue using the existing JOBSAGE API and database.
8. Avoid creating a second disconnected backend or duplicate business logic.

The app must feel like the JOBSAGE website was deliberately adapted for mobile—not like an unrelated redesign and not like a basic website placed inside a blank wrapper.

Use a hybrid architecture.

Use artifacts/jobsage-web as the canonical product UI.

Do not manually rewrite every website page as an incomplete React Native version. That would create two divergent products.

Build a production React Native WebView workspace in artifacts/jobsage-mobile that loads the configured JOBSAGE production or staging origin.

It must support:

- Secure authentication
- Cookie/session synchronization
- Navigation history
- Android hardware back button
- Internal and external URL handling
- File selection
- Camera/photo selection
- File uploads
- Downloads
- PDF/document viewing

- Calendar links
- Deep links

- Retry handling
- Session expiry
- Logout synchronization
- Safe-area insets
- Keyboard handling
- Loading indicators
- Theme synchronization
- Pull-to-refresh only where it cannot damage form state

Do not inject a long-lived authentication token into:

- Page JavaScript
- localStorage
- Query parameters
- URLs
- Console logs

- Single use
- Short lived

- Validated server-side
- Removed after exchange
- Protected against replay
- Audited without logging secrets

Preserve CSRF and session-security controls.

7. SMART APPLY IN-APP BROWSER
==================================================

Mobile Chrome does not support normal Chrome extensions. Recreate Smart Apply inside a JOBSAGE-controlled in-app application browser.

When a user selects Apply from a JOBSAGE vacancy:

1. Validate the vacancy and destination.
2. Save/register the outbound application.
3. Open the employer or ATS site inside the Smart Apply browser.
4. Preserve the trusted vacancy context through redirects.
5. Show a JOBSAGE assistant bottom sheet or side sheet.
6. Allow normal employer-site login, SSO, CAPTCHA and manual input.
7. Keep the user in control of every final submission.

Do not activate Smart Apply because a random URL contains ref=jobsage.

Only activate it from a trusted, authenticated JOBSAGE application event.

EXISTING WORK TO PRESERVE

Inspect:

- artifacts/jobsage-web/src/components/MobileAssistedWorkspaceHost.tsx
- artifacts/jobsage-web/src/lib/assistedApplication.ts
- artifacts/jobsage-web/src/lib/desktopApplicationReturn.ts
- artifacts/jobsage-web/src/lib/trackedOutbound.ts

When JOBSAGE is running inside the native app, supported application links should open in the native Smart Apply browser rather than the external system browser.

- Vacancy identifier

- Timestamp

- Allowed action
- Payload shape and size

Requirements:

- Only allow HTTPS employer destinations.
- Block javascript:, data: and unsafe custom URLs.
- Never execute arbitrary JavaScript received from a webpage.
- Never expose access tokens to employer pages.
- Never expose profile data unless needed for a user-requested fill action.
- Do not log CV contents, generated answers or sensitive profile fields.
- Apply origin allowlists to first-party privileged messages.
- Treat employer pages as untrusted content.
- Prevent employer pages from impersonating JOBSAGE bridge messages.
